# 🏫 School Intranet – Plateforme de gestion scolaire

> Une plateforme centralisée pour digitaliser, organiser et simplifier la gestion administrative, pédagogique et organisationnelle d'un établissement d'enseignement supérieur.

---

## 📌 1. Présentation du projet

**School Intranet** est une application web destinée à un établissement d'enseignement supérieur. Elle permet de centraliser les différents services de l'école dans un espace numérique unique, accessible aux étudiants, enseignants, membres de l'administration et responsables pédagogiques.

L'objectif est de faciliter la communication interne, automatiser les tâches administratives, améliorer le suivi pédagogique et offrir une meilleure expérience à l'ensemble des utilisateurs.

### Objectifs principaux

- Centraliser les informations et les ressources de l'établissement.
- Faciliter la communication entre les différents utilisateurs.
- Simplifier la gestion des étudiants et des enseignants.
- Digitaliser les processus administratifs.
- Gérer les emplois du temps et les activités pédagogiques.
- Faciliter le partage de documents et de supports de cours.
- Suivre les absences, les notes et les résultats.
- Fournir des tableaux de bord adaptés à chaque profil.

## 👥 2. Gestion des utilisateurs et des rôles

L'application repose sur un système de gestion des rôles et des permissions (RBAC).

Chaque utilisateur dispose d'un espace personnalisé selon ses responsabilités.

### 2.1 Administrateur (Super Admin)

L'administrateur possède un accès global à la plateforme.

Fonctionnalités :
- Gérer les comptes utilisateurs.
- Créer, modifier et supprimer des comptes.
- Attribuer les rôles et les permissions.
- Gérer les filières et les formations.
- Gérer les promotions et les groupes.
- Consulter les statistiques générales.
- Gérer les annonces globales.
- Superviser les activités de la plateforme.
- Consulter les journaux d'activité.
- Configurer les paramètres de l'intranet.

### 2.2 Administration

L'administration dispose d'un espace dédié à la gestion quotidienne de l'établissement.

Fonctionnalités :
- Consulter les listes des étudiants.
- Gérer les dossiers administratifs.
- Gérer les inscriptions.
- Publier des annonces.
- Gérer les documents administratifs.
- Consulter les emplois du temps.
- Gérer les salles et les ressources.
- Communiquer avec les étudiants et les enseignants.

### 2.3 Responsable pédagogique

Fonctionnalités :
- Gérer les filières et les modules.
- Affecter les enseignants aux modules.
- Organiser les emplois du temps.
- Suivre les activités pédagogiques.
- Superviser les évaluations.
- Consulter les absences.
- Suivre les résultats des étudiants.
- Gérer les événements pédagogiques.

### 2.4 Enseignant

Fonctionnalités :
- Consulter son emploi du temps.
- Consulter ses groupes et ses étudiants.
- Publier des supports de cours.
- Déposer des travaux pratiques.
- Publier des devoirs et des évaluations.
- Saisir les notes.
- Enregistrer les absences.
- Publier des annonces destinées à ses groupes.
- Consulter les informations pédagogiques.

### 2.5 Étudiant

Fonctionnalités :
- Consulter son tableau de bord.
- Consulter son emploi du temps.
- Accéder aux supports de cours.
- Télécharger les documents pédagogiques.
- Consulter ses notes et résultats.
- Consulter ses absences.
- Consulter les annonces.

- Consulter les événements de l'établissement.

## 🏗️ 5. Architecture technique

Le projet repose sur une architecture client-serveur organisée en plusieurs couches.

### Frontend

- Next.js
- React
- TypeScript
- Tailwind CSS
- Shadcn/UI
- React Hook Form
- Zod
- Axios ou Fetch API

### Backend

- Node.js
- Express.js
- TypeScript
- REST API
- JWT Authentication

- Middleware de gestion des permissions

### Base de données

- MongoDB
- Mongoose

### Services complémentaires

- Cloudinary pour les fichiers et les images.
- Socket.IO pour les notifications en temps réel.
- Nodemailer pour les emails.
- GitHub pour le versionnement.
- Vercel pour le frontend.
- Railway pour le backend.

## 🔐 7. Sécurité

La sécurité est un élément central de l'application.

Mesures à mettre en place :

- Authentification sécurisée.
- Hashage des mots de passe avec Bcrypt.
- Gestion des rôles et permissions.
- Protection des routes frontend et backend.
- Validation des données côté serveur.
- Protection contre les injections.
- Rate limiting.
- Gestion sécurisée des tokens.
- Variables sensibles dans les fichiers d'environnement.
- Contrôle des accès aux documents.
- Journalisation des actions sensibles.
- Gestion des sessions et déconnexion.

Les permissions doivent impérativement être vérifiées côté backend. Masquer un bouton dans le frontend ne constitue pas une protection suffisante.

## ⚙️ 8. Installation et configuration

### Prérequis

- Node.js
- npm
- MongoDB Atlas ou MongoDB local
- Git
- Compte Vercel
- Compte Railway

### 8.1 Cloner le projet

```bash
git clone https://github.com/USERNAME/school-intranet.git

cd school-intranet
```

### 8.2 Installer le frontend

```bash
cd frontend
npm install
```

Créer un fichier `.env.local` :

```env
NEXT_PUBLIC_API_URL=http://localhost:5000/api
```

Lancer le frontend :

```bash
npm run dev
```

### 8.3 Installer le backend

```bash
cd backend
npm install
```

Créer un fichier `.env` :

```env
PORT=5000
NODE_ENV=development

MONGODB_URI=mongodb+srv://USER:PASSWORD@cluster.mongodb.net/school_intranet

JWT_SECRET=your_secret_key

FRONTEND_URL=http://localhost:3000

CLOUDINARY_CLOUD_NAME=
CLOUDINARY_API_KEY=
CLOUDINARY_API_SECRET=

SMTP_HOST=
SMTP_PORT=
SMTP_USER=
SMTP_PASSWORD=
```

Lancer le backend :

```bash
npm run dev
```

## 📌 13. Conventions de développement

Pour assurer la maintenabilité du projet :

- Utiliser TypeScript sur le frontend et le backend.
- Respecter une architecture modulaire.
- Séparer les routes, contrôleurs et services.
- Utiliser des composants React réutilisables.
- Centraliser les appels API.
- Valider les données côté client et serveur.
- Documenter les endpoints.
- Utiliser des branches Git.
- Effectuer des commits explicites.
- Ne jamais publier de secrets dans GitHub.

### Convention Git

```text
main        → Production
develop     → Développement
feature/*   → Nouvelles fonctionnalités
fix/*       → Corrections
hotfix/*    → Corrections urgentes
```

Exemples de commits :

```text
feat: add student management
feat: implement schedule module
fix: correct authentication middleware
refactor: improve API architecture
docs: update project README
```
